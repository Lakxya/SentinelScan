# Milestone 07 - Kubernetes Security Analysis Scanner

- **Status**: `COMPLETED`
- **Release Version**: `v0.7.0`
- **Focus**: Building a static Kubernetes security scanner (`KubernetesScanner`) inspecting YAML/JSON deployment manifests for security misconfigurations, privileged containers, root users, missing resource limits, host namespaces, privilege escalation, unbounded RBAC permissions, and unencrypted secret data without executing `kubectl`, `helm`, or API server commands.

---

## 🎯 1. Goals

Implement a static Kubernetes manifest scanner (`KubernetesScanner`) integrating into SentinelScan's `BaseScanner` interface under `Category.KUBERNETES`, discovering manifest files (`*.yaml`, `*.yml`, `*.json`), parsing multi-document YAML streams safely using `PyYAML` `SafeLoader`, evaluating workload controllers and RBAC policies, and providing CLI support via `sentinelscan k8s <path>`.

---

## 🛠️ 2. Actual Capabilities Implemented

### 2.1 Safe Multi-Document YAML/JSON Parser
- **PyYAML SafeLoader (`yaml.safe_load_all()`)**: Parses single and multi-document YAML files separated by `---` into individual AST resource objects without executing arbitrary Python class constructors.
- **Resource Identification**: Validates `apiVersion` and `kind` fields (`Pod`, `Deployment`, `StatefulSet`, `DaemonSet`, `ReplicaSet`, `Job`, `CronJob`, `Service`, `ConfigMap`, `Secret`, `Role`, `ClusterRole`, `RoleBinding`, `ClusterRoleBinding`), safely ignoring non-Kubernetes YAML files (CI pipelines, Docker Compose).
- **Workload Spec Navigation**: Seamlessly extracts Pod templates across workload controllers (`Pod`, `Deployment`, `StatefulSet`, `DaemonSet`, `ReplicaSet`, `Job`, `CronJob`).

### 2.2 Security Rules Implemented

| Rule ID | Title | Severity | Confidence | Target Scope | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`K8S-PRIVILEGED-CONTAINER`** | Privileged Container Requested | `CRITICAL` | `HIGH` | Container Spec | `securityContext.privileged: true`. |
| **`K8S-ROOT-CONTAINER`** | Container Configured / Defaulting to Root | `HIGH` | `HIGH` / `MEDIUM` | Pod & Container Spec | `runAsUser: 0` or `runAsNonRoot: false` (`Confidence.HIGH`); or missing explicit non-root spec (`Confidence.MEDIUM`). |
| **`K8S-MISSING-RESOURCE-LIMITS`** | Container Missing CPU or Memory Limits | `MEDIUM` | `HIGH` | Container Spec | Container spec lacks `resources.limits.cpu` or `resources.limits.memory`. |
| **`K8S-HOST-NAMESPACES`** | Host Namespace Access Enabled | `HIGH` | `HIGH` | Pod Spec | Pod spec sets `hostNetwork: true`, `hostPID: true`, or `hostIPC: true`. |
| **`K8S-ALLOW-PRIVILEGE-ESCALATION`** | Container Allows Privilege Escalation | `MEDIUM` | `HIGH` | Container Spec | `securityContext.allowPrivilegeEscalation: true` or unconfigured. |
| **`K8S-UNBOUNDED-RBAC-CLUSTER-ADMIN`** | Unbounded RBAC Permissions / Cluster-Admin | `HIGH` | `HIGH` | Role / Binding | `ClusterRole`/`Role` with wildcard verbs `["*"]` and resources `["*"]` or binding to `cluster-admin`. |
| **`K8S-SECRET-IN-CONFIGMAP`** | Sensitive Secret Embedded in ConfigMap | `HIGH` | `HIGH` | ConfigMap Data | ConfigMap keys match secret patterns with non-placeholder values (masked in findings). |
| **`K8S-PLAIN-TEXT-SECRET-DATA`** | Raw Unencrypted Secret Data in Manifest | `MEDIUM` | `HIGH` | Secret Manifest | `Secret` resource containing raw `stringData` or base64-encoded `data` keys (masked in findings). |

### 2.3 False Positive Mitigation & Intelligence
- **Root User Confidence Nuances**:
  - `runAsUser: 0` or `runAsNonRoot: false` $\rightarrow$ `Severity.HIGH`, `Confidence.HIGH`.
  - Pod-level `runAsNonRoot: true` or `runAsUser: 10001` is inherited by containers $\rightarrow$ 0 findings.
  - Container-level explicit `runAsNonRoot: true` or non-zero `runAsUser` $\rightarrow$ 0 findings.
  - Unconfigured non-root status at both Pod and container level $\rightarrow$ `Severity.HIGH`, `Confidence.MEDIUM`.
- **Secret Semantics & Masking**:
  - Distinguishes raw `stringData` from base64-encoded `data`.
  - Secret values are strictly masked using `mask_token()` before constructing finding objects.

### 2.4 Security & Privacy Safeguards
- **Zero Command Execution**: Never runs `kubectl`, `helm`, `kustomize`, `minikube`, or shell commands.
- **Zero Network Access**: Performs 100% offline local static analysis. Calls zero cloud or cluster APIs.
- **Zero Secret Leakage**: Raw secret values are masked in findings, logs, reports, and test output.
- **Read-Only**: Target files are never modified.

## 📌 5. Known Limitations at Milestone 07 Completion

- Static manifest analysis inspects declared Kubernetes YAML/JSON text. It does not inspect live cluster runtime state, admission controller mutations (e.g. Kyverno/OPA Gatekeeper), or image binaries.
